## 首次偏差与根因边界

1. **路由输入缺少会话语义。** Hook 直接检索最新字符串。短追问无法指向既有任务；选择框回复的内部 ID、JSON 字段名也参与匹配。
2. **候选本身错配。** 真实 IDE 修复曾收到考试团队、品牌策划、特定产品调试候选；新的完整任务复放仍收到组学诊断、行程 JSON 等条目。不能将合理拒用无关候选解释成模型“懒得使用专家”。
3. **类目预算放在截断之后。** 图先返回全库前 8，Hook 才限制专家 2、Skill 4、MCP 2；已经截掉的专家无法回来。这个结构性问题存在，但不是专家一定相关的证据。
4. **embedding 存在但不够。** 全局图有 19,753 节点、447 个完整专家，中文多语模型确实启用。对同一具体任务，向量专家前列仍出现组学模块，不能仅修最终排序就宣称解决。

因此不采用上轮“服务容量导致该对话未用专家”的断言。常驻服务的 4 次早期请求超时，但后续请求恢复；隔离同图为 101–540ms，常驻后续新查询约 2.7–3.5s。这不是受控性能比较，也没有确定超时的唯一原因。

## 已修改并部署

仅修改 `skill-router.mjs` 的检索输入边界：

- 短承接句从 Codex 提供的 transcript 读取最近实际用户任务，最多读尾部 1MiB，不扫描整个会话库、不持久化用户文本。
- 新话题不继承；没有可靠上下文的承接句不制造随机推荐。
- 选择框回复提取问题与答案，不把传输字段、内部 ID 送去检索。
- 排除明显凭据和环境/指令注入消息；承接句识别使用有界、无回溯的分词。

仓库安装源与全局安装文件 SHA-256 均为 `191bad2b9f064987381b71c706b846f1431e71e289c33c661db92b726b2783b0`。部署后独立 app-server `hooks/list` 返回 SessionStart、两个 UserPromptSubmit、Stop 均 enabled/trusted；没有写信任哈希、改认证、重启用户 IDE或修改目标线程。

## 外部借鉴：读过原实现，不搬结论

- [LlamaIndex](https://github.com/run-llama/llama_index)（GitHub API 实查 52,662 stars）：[原始 condense_question.py](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/chat_engine/condense_question.py) 先把历史与追问恢复为独立问题，再检索。本轮只借鉴输入恢复原则，没有引入每轮额外付费 LLM 调用。
- [Semantic Router](https://github.com/aurelio-labs/semantic-router)（实查 3,977 stars）：[BaseRouter](https://github.com/aurelio-labs/semantic-router/blob/main/semantic_router/routers/base.py) 区分排序、校准与可拒答决策。不能将我们的 RRF score 或 low/medium 直接当概率，也不能凭空套阈值。
- [Stack Overflow 已接受答案](https://stackoverflow.com/a/30553851)：minimum_should_match 应在拥有查询语义的边界生效，而不是依赖下游过滤。本例是 Elasticsearch 的局部答案，不是 GraphToolCall 相关性提升的实验证据；没有直接搬用它的阈值。
- [Codex 官方源代码的 Hook 输入 schema](https://github.com/openai/codex/blob/main/codex-rs/hooks/schema/generated/user-prompt-submit.command.input.schema.json) 与 [序列化实现](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/events/user_prompt_submit.rs) 均明确有 transcript_path。官方文档网页抓取返回 403，未把搜索摘要当作已读文档；平台字段以官方原始实现补证。

最初批量搜索有空结果、显式目标缺失和无关结果；仅针对缺失方向补查了原始 GitHub API、源码和 SO answer body。stars 是选源依据，不是效果证明。
