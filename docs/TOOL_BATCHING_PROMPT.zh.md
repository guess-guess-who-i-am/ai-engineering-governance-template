## 每次用户消息的短提醒——完整中文译文

收齐当前已经知道、已经就绪、相互独立的操作，形成一个逻辑批次，不要每做一项就返回模型一轮。互补查询一起提交，已经知道的网页一起读取，并遵守当前工具的 schema。优先原生批量接口；否则使用当前实际暴露的并发工具，只有 Shell 时使用 `~/.codex/tools/parallel-run.mjs`。从4与就绪操作数的较小值开始，成功后渐增，争用时减半；20只是上限。保留依赖关系和串行安全；需要语义判断时回到模型；不要虚构工作。

这是非固定轮的全部调度提醒。第1、4、7……轮使用下面的完整版本替代它，二者不会同时注入。SessionStart在启动、恢复、清理和压缩时恢复固定方法论并重置轮次；完整调度契约在下一条 UserPromptSubmit 注入。

## 固定轮完整调度契约——完整中文译文

每轮用户消息和之后的每个工具波次都应用这份执行契约。20是安全硬上限，绝不是利用率目标。

- 先构造最小而有用的依赖图：识别前置条件、独立分支、共享可变状态、限流、破坏性影响，以及每个消费者实际需要的结果。
- 发出工具波次前，收齐当前已经知道、已经就绪、相互独立的操作。把就绪集合当作一个逻辑批次提交，不要每做一项就让模型再运行一轮。同类工作优先使用原生批量接口或一条有界命令；独立的混合工具复用正在运行的执行封装。不要每个条目都产生一次模型往返，也不要为一个共享进程即可完成的工作额外打开终端。
- 搜索时，互补查询一起提交；已知网页一起抓取。遵守当前工具 schema（目前 web.run 每次最多接受4条 search_query）；并发上限不会扩大 API 限制。批次返回后，根据证据判断是否存在值得下一批补充的具体缺口，不要重复近乎相同的查询。
- 普通只读波次从4与就绪独立操作数的较小值开始。原生批量 API 如果提供初始宽度选项，也请求同样的宽度。只在波次成功且争用低时逐渐增加；失败、超时、限流或资源争用后减半。始终不超过20。
- 每个波次只执行依赖图中已就绪的节点。对于有状态、破坏性、受限流或批准约束、尚不确定或彼此干扰的操作，保持并发为1，除非所属接口明确保证并行安全。
- 如果能减少模型往返，就使用一个外层 functions.exec；只有已证实独立的操作才使用 Promise.all。把机械上已确定的轮询、收集和验证继续留在该封装内。
- 只使用当前会话实际暴露的工具。如果宿主只有 Shell，通过已安装的 Node 依赖图执行器 `~/.codex/tools/parallel-run.mjs` 运行独立就绪命令；禁止写入时，传入 `-` 并通过标准输入发送 JSON 计划。不要为每条就绪命令单独让模型运行一轮，也不要假定 functions.exec 一定存在。每个任务具有 id、command、args、dependsOn、safety；无关可选值省略。
- 当结果需要语义解释、依赖图变化、出现不确定性、需要用户输入或必须作破坏性决策时，回到模型。
- 保留来源引用和逐项结果，包括部分失败。去除重复证据；不要用重复输出淹没上下文，不要因为一个同组条目失败就丢弃成功条目，也不要静默更换提供方。绝不能把批量提交当作底层 HTTP 已并发的证据。
- 必须使用的主要 Skill 先完整读取。修改之后，把独立检查合成一批，但保留生产者与消费者的先后顺序，并运行足以证伪结论的最窄验证。
- 记录波次成员、并发宽度、耗时、退出码、重试、超时及因依赖而跳过的消费者。真实重叠才是证据，配置的最大值不是。
- 不要为了填满容量虚构工作，不要把一个高效操作拆成多个终端，不要隐藏依赖、削弱检查或在没有执行时间区间重叠时声称并发。

## 一个例子与验证边界

已经知道需要查官方说明、实现仓库、失败案例时，先组成互补查询批次；结果回来选出待核验网页，再组成读页批次；读完才作方案判断。后一步的 URL 来自前一步，因此不能假装从头到尾没有依赖。

`test-hook-cadence-mac.mjs` 检查每轮实际输出包含就绪集合、查询批量、已知网页批量和接口边界，完整包仍只在固定轮出现；这证明注入，不证明模型必然服从。`test-methodology-target-ownership.mjs` 用隔离消费者验证发布目标归属，并故意破坏目标确认门禁会拒绝。真实模型测试记录 webSearch 的 queries 数组，区分“请求已合批”与未经观测的底层 HTTP 并发。提示词不能承诺任意任务每轮都有固定数量的工具调用。
