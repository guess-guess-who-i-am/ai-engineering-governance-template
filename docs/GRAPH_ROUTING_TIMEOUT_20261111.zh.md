# 全局检索超时：紧凑缓存与预热发布

本轮仅修改路由及其发布路径，保留 `codex/high-concurrency-global-routing`，不合并 main；不修改 IDE、模型、业务任务树或认证配置。

## 已证实的原因

- 现场三条约 21KB 的原始指令均在约 55.15 秒退出，stderr 报超时，退出码却为 0。独立重放旧常驻服务有时仅需 2.62–4.28 秒，不能据此推定永久死锁。
- 两份重排缓存的 `texts.npy` 使用定长 Unicode 数组，少数长描述把所有行补齐，未压缩成员分别为 2,022,836,672 和 2,027,524,952 字节。仅流式读取仍需解压全部填充数据，四进程冷池约 49 秒，故未采用该中间方案。
- 原实现直接替换图文件，各计算进程在业务查询中发现版本变化后同步重载。常驻不等于新图已经初始化；图更新可让正常请求再次承担冷加载。
- 准备脚本最初遗漏 `ToolGraph.save(..., metadata=graph.metadata)`，丢失自定义 metadata，被全图一致性断言拒绝。修正后重新通过，未放宽断言。

## 最终变更及契约

完整有序描述采用 UTF-8 JSON 字节数组，格式标识为 `utf8-json-texts/v1`，不使用 pickle。构建器、签名、metadata 和读取器一起更新；旧格式必须重建，不提供旧格式回退。保留完整文本身份、SHA-256、向量维度和有限值校验。

两种语言独立重编码与原向量逐位一致，发布资产仍使用原认证向量；除 `metadata.description_embeddings` 和保存时间外，整张 19,756 资源图的 JSON 内容完全一致。两份文本成员降至 8,131,838 和 8,217,334 字节。

活动 Worker 的本地协议增加 `operation: publish` 与候选文件路径。发布者等待候选四进程完成双语图、模型、预过滤和缓存初始化，收到 `prewarmed: true` 后才算提交。候选准备期间，旧文件与旧代际保持可见；提交时原子替换图并切换进程池，旧请求自然排空。每代图及 sidecar 由硬链接快照固定，失败候选不改变当前图。响应的 `generation` 标识服务代际，`loads` 保留单计算进程加载次数含义。

图构建器和资源发布脚本均使用此边界。180 秒仅用于后台候选准备，不改变业务请求的 55 秒截止。无活动服务时允许安装初始图；首次启动及绕过发布者直接改文件仍有冷加载成本。检索/子 Hook 错误现在退出非零，同时保留成功兄弟 Hook 的输出。

## 实测

同一台 16GiB Mac，四个计算进程；不调用付费模型。并发验证上限 20。

| 实验 | 结果 |
|---|---|
| 旧版四进程冷池、三条原始指令 | 48.36–48.65 秒，全成功 |
| 最终候选首次冷池、三条原始指令 | 43.01–43.20 秒，全成功；所有结果字段及排序与旧版完全相等 |
| 20 条不同长查询并发 | 20/20 成功，2.56–12.11 秒；四个计算进程均参与，调用区间真实重叠 |
| 候选全图后台预热 | 40.19 秒 |
| 预热期间连续探测 | 26/26 成功，最长 1.99 秒，仍明确标识旧代际 |
| 提交后原始三指令 | 3.77–3.84 秒，全成功，全部结果及排序不变，新代际 |
| 回归 | 18 项 Worker、2 项缓存、真实双语完整编码构建、12 项发布器、错误传播及桌面路由测试通过 |

相同离线环境下，单进程总计约 22.82 秒：JSON 图加载约 3.7 秒、中文内容与词索引各约 2–3 秒、英文图约 1.1 秒、英文/中文模型初始化约 3.43/1.47 秒、两份紧凑缓存各约 0.17–0.18 秒。完整分阶段日志保留在本机证据目录；这些阶段包含嵌套调用，不能简单相加。

曾在未设置离线环境的独立剖析脚本中测得更长的模型初始化；改成直接 CPU 加载没有改善，因此未修改模型或设备策略，该组结果不代表生产服务。100 条不同长请求的整波过载断言曾失败，保留原始日志，不作为本轮支持范围或成功证据；后续验收最多 20 并发。

## 本机部署

已备份至 `~/.codex/backups/graph-timeout-20261111`，排空并恢复仅检索服务，匹配图与三个 Hook 已发布，仓库与全局文件 SHA-256 一致。活动服务 PID 42794，双语及全部重排描述缓存预热成功；真实 router 三条原始指令并发耗时 3.50–3.60 秒，均退出 0、无 stderr。完整 dispatcher 随后命中缓存，耗时 143–147ms；部署后 20 条不同长请求均成功，四进程参与，耗时 2.87–16.53 秒。持久 Finder 部署源同步路由文件和实际依赖，未运行全配置安装器；模型、认证和 IDE 配置未改动。

`DEPLOYED_AND_PREWARMED.json` 是本机就绪收据。当前工作区原有 56 个历史备份删除导致全仓文档门禁失败；保留这些无关改动，在 HEAD 加本轮变更的隔离候选上完整 15 项质量门禁通过。

## 证据与边界

原始指令、完整候选结果、时间区间、冷/热池日志、红/绿测试及部署收据保留在 `~/.codex/cache/graph-timeout-20261111`，不提交用户原始长指令。可提交的脱敏摘要见 [验证数据](evidence/graph-routing-20261111.json)。关键原始文件包括 `compact-assets.json`、`compact-lifecycle.json`、`compact-detailed-stages.jsonl`、`prewarm-publish-red.log` 和 `worker-final-18.log`。

没有取得故障发生时的 Python 栈，故不能唯一追溯原始 55 秒事件；已证实数据布局放大和业务路径同步重载，并分别修正。完全冷启动仍为几十秒，不能宣称所有场景均为 3–4 秒；本机更新路径已独立实测，194 与其他系统未部署此轮修改。
