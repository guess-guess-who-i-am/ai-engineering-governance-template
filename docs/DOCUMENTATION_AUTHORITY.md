# 文档权威与联动

每类事实只保留一个权威位置。其他文档可以链接或摘要，但不能维护第二份可独立变化的定义。

## 权威地图

| 事实 | 权威位置 | 何时读取 |
|---|---|---|
| 用户结果、当前范围 | `PROJECT_BRIEF.md` | 新项目、范围变化、优先级冲突 |
| 术语、实体、不变量、所有权 | `CONTEXT.md` | 领域含义或责任边界变化 |
| 视觉与交互语言 | `DESIGN.md` | UI 设计、实现或审查 |
| 用户可观察行为 | `requirements/user-stories/` | 产品行为、验收或证据变化 |
| 阶段测试、缺陷复测与测试交接事实 | `requirements/test-runs/` | 阶段性交付、跨边界验证、缺陷修复或发布候选 |
| 跨 Story 用户旅程 | `requirements/user-journeys/` | 一个结果跨多个组件、模块或阶段 |
| 高影响实现路线 | `requirements/plans/` | 契约、数据、迁移、发布或回滚存在实质风险 |
| 公共接口与失败语义 | 拥有方 contract/schema | 生产者或消费者行为变化 |
| 测试类别与命令 | `quality/gates.json` | 技术栈、CI 或发布证据变化 |
| 持久、稀缺、付费或承载数据的资源 | `docs/RESOURCE_REGISTRY.md` | 新增服务、端口、数据、模型、GPU、账号或长期进程 |
| 发布事实 | `VERSION`、`CHANGELOG.md`、tag 与制品摘要 | 发布或 Hotfix |
| 专项工作方法 | 匹配的 `.agents/skills/*/SKILL.md` | 仅在触发条件明确命中时 |

代码和测试是实际行为的权威。文档与实现冲突时，不用兼容层掩盖冲突：先确认应有行为，再同步拥有方及消费者。

## 联动规则

- 目标或范围变化：先改 brief 或 Story，再改实现与证据。
- 阶段测试或缺陷复测：执行记录回链 Story、AC、精确提交或工作区、构建、环境和可回溯工件；普通局部单元测试不创建重复文档。
- 术语、实体、状态或所有权变化：先改 `CONTEXT.md`，再同步 Story、contract、代码和测试。
- 公共行为变化：先改拥有方 contract，再同步生产者、所有消费者和端到端 Flow。
- 数据结构变化：同步迁移、兼容、回填、恢复和真实引擎验证。
- UI 语言变化：同步 `DESIGN.md`、公共组件、基准页面和浏览器证据。
- 技术栈或质量声明变化：同步 `quality/gates.json`、锁文件、CI 和运行说明。
- 资源变化：同步资源登记、配置引用、健康检查、清理方式和负责人。

## Agent 读取规则

日常局部修改先读最近代码、测试、Story 和最近的 `AGENTS.md`。只有当前任务触及上表边界时才读取对应权威；不要为了“了解项目”预读全部文档。
