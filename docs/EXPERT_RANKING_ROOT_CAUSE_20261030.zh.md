# 专家推荐排序：根因、修复与实验边界

后续候选池部署、GTE/BGE/4B 模型实测与剩余职责错配见[修复进展与实测报告](EXPERT_RANKING_REPAIR_20261030.zh.md)。下文模型下载和实验状态为较早一轮记录。

**评价口径已审计：49/68仅为不完整标签的目标名称命中，不能称推荐正确率。68条来自34个中英成对场景；另一席被替换成错误专家时分数不变。详见[指标根因审计](EXPERT_METRIC_AUDIT_20261030.zh.md)。**

当前只修复了确定的名称证据缺陷，**尚未解决自然需求下的精准选专家**。原专家包、主角色、成员流程、图关系和向量不变；失败实验不进入安装配置。

## 第一处分歧

1. GraphToolCall 0.46 的名称加分直接读取图内部 ID。请求中的数字可能匹配包哈希；纯中文归一化为空串后会匹配所有 ID。修复后，专家、Skill、MCP 服务读取原声明名称，原生 MCP 读取原工具名，图 ID 继续用于区分资源。空串不算名称证据。
2. 语义召回仍会把“客户猜编号访问别人账单”理解成发票审核；把“结账全站故障”理解成财务月结。不是所有错配都发生在最后排序。
3. 同一冻结图的 68 条自然需求中，预设目标专家前两席命中仍为 **49/68**。19 条目标未命中里，11 条所有目标都在候选池外，8 条至少一个目标已入池但排低。后置重排无法找回池外目标。
4. 原角色能力范围已经用于返回专家的说明，但检索表示仍依赖简介、关键词和小向量模型。把简介直接替换成角色原文、隔离专家类别或更换融合公式，均没有稳定改善；不能把“展示说明修好”当作“检索表示修好”。

这 19 条是**目标名称未命中**，不是 19 条已证实的任务失败。例如考试复习返回 `exam-preparation-planner`，与其原角色明确相符；完整软件交付返回 `mvp-dev-expert-team`，原角色确实组织 7 位专家完成 6 阶段生命周期。这两条暴露了固定目标标签漏记等价专家的问题。没有完成逐席适用性评审，不能报告最终推荐准确率。

## 已发布的确定修复

- 名称证据与图内部 ID 分离，保留库原有重叠权重和显式名称优先规则；这些权重不是经本轮校准的任务成功概率。
- 同名模块保留独立 ID、独立分数，不因同名拒绝全局加载；中英文显式名称共用一次加分下限。
- 8 项名称回归覆盖空串、数字哈希、真实中英文名称、同名模块、混合名称、原生工具及其他资源类别。
- 只替换全局常驻 worker 的检索代码，更新相应输入身份；受保护 AST、图和向量文件经比较保持一致，不修改 Hook 信任记录。
- 实验工具增加输入冻结校验；线上核验必须使用相同图和代码的预测，拒绝空测试集。

Tool-Embed 与 Qwen 向量的暖 MPS 查询分别约 49、62 毫秒。实验进程峰值约 6.1、4.7 GiB，含图、模型和构建临时对象，**不能当作新增常驻内存**。Qwen 重排 CPU 动态 int8 的 4 对短输入仍约 4.9–5.1 秒。上述模型均未注册到全局 worker。

完整主角色分段实验保留每位专家一个结果，没有拆包或增加生产候选。借鉴 PARADE 讨论的 MaxP/平均聚合，使用现有多语编码器建立 15,933 个片段。原论文 225-token 窗口超过本模型限制，因此按模型实际长度限制为126个正文 token、重叠25 token，并逐片验证加特殊 token 后不超过128。第一轮解码再编码导致部分片段变成129 token，该轮已作废，表内是修正后的结果。这是片段余弦聚合实验，不是训练过的 ColBERT/PARADE 模型复现。

## 生产入口验证与限制

冻结图 SHA-256：`9ba3056fe3af40e4f6d004b879bf047034faa67dcdecef356647237f10efcb91`。

仓库外目录已通过安装的 Hook 获得 2 专家＋4 Skill＋2 MCP 推荐。第一版名称修复的 74 次真实 socket 请求全部成功，8 个客户端同时发出，由 4 个常驻查询进程处理，8.51 秒完成且全部匹配冻结预测；这是检索服务证据，不是专家执行或整个 Agent 任务提速的证据。最终全类别版本复测同样 74/74 成功、4 个查询进程、8 个客户端重叠，8.42 秒完成，全部匹配冻结预测。

针对本次混合检索修复需求，Hook 仍推荐偏向制作专家包的 `skill-smith` 与 `skillhub-charity-expert-team`，所以本需求下的相关性缺口可直接复现，不能宣称“自动精准推荐已修好”。

部分角色还有宿主依赖。例如 `sre-expert` 原角色明确要求 CloudQ 可用后才处理请求；角色名相关不代表本机能执行。原包保持完整，不以虚构工具或替换流程掩盖这个限制。

下一步应先按原角色对真实返回两席补齐适用性判断，区分等价推荐、局部适用、领域错配和宿主阻塞，再针对仍然错误的需求改进表示与候选召回。继续只调末端权重没有解决 11 条池外目标的机制。

## 来源与复现

- [Re-Invoke](https://aclanthology.org/2024.findings-emnlp.270/)，DOI `10.18653/v1/2024.findings-emnlp.270`：借鉴离线请求扩写与在线意图理解，本轮只测试局部机制，非完整复现。该文是 Findings。
- [TOIS 检索融合研究](https://doi.org/10.1145/3596512)：比较 RRF 与分数归一化融合；本轮没有用测试标签拟合融合权重。
- [Qwen3-Embedding 官方仓库](https://github.com/QwenLM/Qwen3-Embedding)：采用官方 CrossEncoder、任务指令与 last-token pooling，不能用其官方榜单替代本机结果。
- [BGE-M3 官方实现](https://github.com/FlagOpen/FlagEmbedding/tree/master/research/BGE_M3)，DOI `10.18653/v1/2024.findings-acl.137`：核实无查询指令、1024 维、8192 长度及多语支持；因权重不完整，没有测试性能。该文也是 Findings。
- [Stack Overflow 78785656](https://stackoverflow.com/questions/78785656)：回答说明 RRF 后再语义重排；不是接受答案，不把其扩大候选数建议用于本系统。新一轮 SO 检索返回的 evaluator 讨论与当前故障不直接相关，没有作为修复依据。
- [Python 正则文档](https://docs.python.org/3.13/library/re.html)：确认 Unicode 字母数字语义；确定性反例来自实际安装的 GraphToolCall 0.46 函数。
- [PARADE](https://doi.org/10.1145/3600088)，TOIS；本轮读取 arXiv `2008.09093v2` 全文，核对225-token窗口、200-token步长及分数/表示聚合的区别，未把本文最大值基线当成其训练模型。
- [ColBERT](https://github.com/stanford-futuredata/ColBERT)，SIGIR 2020，DOI `10.1145/3397271.3401075`：核对官方 README 的离线 token 矩阵与 MaxSim 原理；本轮片段单向量聚合不是 ColBERT。

可迁移测量见 [JSON 证据](evidence/expert-ranking-20261030.json)。完整本机轨迹、模型矩阵与负结果保留在 `.reports/expert-ranking-20261030/`。实验脚本均隔离于生产安装；复现模型方案需另行取得相同模型版本和原角色文档，不上传模型权重或第三方源码。
