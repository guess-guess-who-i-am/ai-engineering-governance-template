# 共享检索进程的延迟回归核查

结论：内存优化确实降低了并发吞吐。不是每个查询都变成32～41秒；这些数字是百路长输入的排队P95。旧记录中的3.77秒同样有真实依据，但对应四个计算进程和短输入。上一轮没有做同条件新旧吞吐对比，不能将“省内存、请求成功”当成性能无退化。

## 固定图与相同输入的对照

旧实现取自`9c5155e`，新实现取自`803d933`；同一Python和同一不可变图，保持模型、类别配额、完整返回记录相同。旧两进程和新单进程两线程顺序运行，预热完成后开始测量；临时服务退出后才运行下一实现，未修改全局服务。旧版不是历史最快的四进程版本。

| 负载 | 旧两进程P95 | 新两线程P95 | 完整记录 |
|---|---:|---:|---|
| 20个请求逐个发送 | 0.658秒 | 0.221秒 | 全部一致 |
| 20个不同短输入并发 | 1.919秒 | 3.456秒 | 全部一致 |
| 20个不同较长输入并发 | 2.344秒 | 3.830秒 | 全部一致 |
| 100个不同短输入并发 | 11.857秒 | 16.627秒 | 全部一致 |

百路短输入在本轮样本中慢约40%，较长输入慢约23%；不能把单轮比例当作任意负载下的固定退化率。两轮对比都完整返回。固定图SHA、全部逐请求耗时与结果摘要见[证据JSON](evidence/graph-latency-20261117.json)。比较输入均附带中文任务标识，使用中文通道；较长输入追加的文字少于此前32～41秒压力测试，不冒充同一负载。主机其它应用和全局服务仍在运行，没有进行随机交叉多轮实验。

## 首次偏离与代码机制

首次行为变化在计算执行边界：`_PreparedGraphPool`的两个独立解释器，被`_PreparedGraphGeneration`的共享线程替换。图和模型只装一份，内存确实减少；但本机CPython 3.13的GIL已确认开启，两个线程不能同时执行Python字节码。

检索并非全部为释放GIL的NumPy或模型运算。已有函数剖析中，一条较长查询的pipeline约0.290秒，候选预过滤约0.206秒，关键词评分约0.118秒；这些是包含关系，不能相加。类别和名称处理、逐工具短语规则、字典构造与排序仍包含大量Python工作。同一模型的编码还保留了互斥保护。因此，两个线程存在时间重叠，不等于保留两个进程的多核吞吐；提高线程数也不能直接绕过这个限制。

这解释了同图对照中“逐个请求更快、并发请求更慢”的方向。尚未分别量出GIL争用、模型锁、调度与主机压力各贡献多少，不能把全部差值都定量归给某一个锁。

## 全局现场与其它放大因素

现场第一轮100个短输入只有34个在55秒内返回；20次首次/重复请求中，一次新查询为13.74秒，重复查询为毫秒级。隔离对比结束后，再向全局服务顺序发送9个新查询，全部成功，范围0.110～0.589秒，双语模型均已就绪。这些现象说明并发排队及运行状态会放大延迟，不能描述成所有日常请求固定耗时几十秒。

现场图的SHA已与固定对照图不同；两者同为338,961,514字节，因此文件大小相等不能作为同图证明。上一轮原版百路P95 53秒、历史四进程3.77秒和本轮11.86秒属于不同状态，不能直接互算提速比例。现场55秒超时的额外放大因素尚未通过服务端逐请求排队/执行追踪完整隔离。

任务中路由另行检查了`routing-checkpoint.mjs`：它按工具能力变化去重，原始参数有长度上限，工具输出正文不进入查询。本轮没有证据支持“把整个聊天或工具输出重新embedding”这一猜测。最初猜测的`mid-task-routing.mjs`不存在，已按实际import定位到前述文件，没有把缺失路径当作源码证据。

## 判断与后续边界

目前只能宣称内存下降、样本结果保持一致；不能宣称同时保持原并发延迟。下一步应保留共享模型和不可变索引，围绕Python候选评分热点验证原生批处理或共享数据下的独立计算执行；同时记录队列等待、模型锁等待和实际计算时间。简单增加线程或延长超时没有解决已确认的多核吞吐损失。

本轮是诊断与结论修正，没有回退全局架构、增加模型副本或修改超时。采用新方案前，必须同时比较单请求、突发、错峰、完整结果、物理内存稳态和峰值，避免再次只验收其中一项。

依据：[Python threading官方文档](https://docs.python.org/3/library/threading.html)明确说明GIL与CPU密集任务限制，free-threaded版本并非默认；本机`sys._is_gil_enabled()`返回true。Stack Overflow官方API检索到的问题没有答案，不能作为修复证明；GitHub搜索结果也未用于支持本轮性能数字。原始对比与现场日志保留于本机`.reports/graph-latency-20261117/`。
