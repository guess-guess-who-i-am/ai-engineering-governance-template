# 技术资料检索自动采用：条件动作与真实测试

2026-10-22。用户要求：“那就继续帮我完成吧，尽量能自动采用”。本轮专门解决已被统一路由推荐、但模型仍不使用的断点；不是修复提供方的全部延时或断流。

## 1. 改在哪里，何时出现

只修改共享路由源 `codex-profile/.codex/hooks/skill-router.mjs`，经既有Windows安装入口备份、发布到用户 `.codex/hooks/skill-router.mjs`。

原来模型只看到“可忽略的候选名单”，所以工具排第一也不等于有执行依据。现新增 `capabilityAction(selected)`：仅当现有GraphToolCall与词法融合的第一项是所属server为technical_research的MCP工具technical_research_batch时，追加一个本轮执行指引。不是把同名的别的server当作本工具，也不对排名较低的偶然候选发指令。

未更改候选评分、四项上限或图结构；没有新增Skill、AGENTS条目、额外规划模型或Hook中的联网预执行。77条方法论原文、9份Prompt、22个受管Skill不变。此新增文字是实施指引，不能冒称用户逐字原话；上面的用户请求独立保留。

每条UserPromptSubmit仍正常运行路由；只有满足首选条件的轮次附带这段约900字符的执行说明，无关轮次没有新增该说明。它不在SessionStart注入，不按第几轮触发，也不把全目录投进模型。

## 2. 英文运行指引的完整中文译文

当本轮需要发现Stack Overflow问题、GitHub仓库或论文等外部资料时，使用选中的technical_research/technical_research_batch作为第一项检索动作，先于等价的网页搜索。用户不需要说出这个工具的名字。通过当前会话实际暴露的MCP/工具接口找到可调用入口，然后将独立的source/query配对一起提交（1–20项）；使用短查询，不需要的可选参数省略。

当前事实使用refresh；否则优先采用明确标注获取时间的缓存。先完整读取必要Skill，再实际执行，而不是只承诺要搜索。之后使用网页工具读取决定性的原始页面或补充未覆盖来源。

用户禁止检索、已有证据足够、任务是GitHub写操作或仅需要通用网页/新闻时，不要调用它。如果工具不可用或失败，报告相应证据和限制；绝不能假装已调用。

这段文字只约束合适任务的默认首选检索，不禁止原文核验，也不能取代用户最新约束。候选仍可被模型按具体任务判为不适用；不是不分情况强制联网。

## 3. 不告诉模型工具名的自然正例

三个测试同时启动，默认模型gpt-6.1-sol、high、自定义Responses提供方，不修改模型/推理/提供方/重试配置。临时只读目录隔离业务文件；用户测试提示没有要求使用MCP、没有写technical_research_batch，也没有告诉它应该批量调用。验收器仅在外部要求实际调用，要求不会进入模型用户任务。

正例A：查Stack Overflow的aiohttp ClientSession讨论和GitHub的httpx仓库，给复用连接的建议。会话 `01a16202-4ab1-71b1-93ea-3e20d7b8d0bd`：

- 实际收到一次条件指引；第一项检索操作是technical_research MCP，而不是网页搜索。
- 模型自行发出一次包含2条查询的请求，两个来源一起执行；Stack Overflow返回10条、GitHub返回1条，合计11条，refresh零缓存。
- 调用完成约6.464秒，全部来源成功，无非法参数重试；之后才读取2个原始页面。最终回答至少引用了1个该批返回的选中来源URL。
- 完整任务88.884秒，最终447个可见字符；提供方期间出现一次带HTTP 403详情的流重连，不能声称端到端延时和精简性已通过。

正例B：为Node.js HTTP并发控制查GitHub的p-limit和Stack Overflow的Promise.all讨论。会话 `01a16202-4ab1-7082-a93d-9edfa70556ed`：

- 实际收到条件指引；第一项检索操作同样为资料MCP。
- 一次提交GitHub与Stack Overflow的2条查询，返回1+10=11条候选，refresh零缓存；调用约965毫秒完成。随后才进行3个网页读取/查找操作。
- 最终回答引用了至少2个该批选中来源URL。完整任务103.697秒、最终735个可见字符；也记录一次带HTTP 403详情的流重连。

两例均为真实模型自主调用，不是程序在Hook里代模型预先检索，不是显式工具指令的复述。只能说本轮两个自然正例通过，不能推导任意问题100%采用。并行启动的样本也不能用来计算公平端到端提速比例。

## 4. 排除任务与机械验证

自然负例：“不要联网、不要调用检索工具，只根据已有知识解释aiohttp与httpx复用”。会话 `01a16202-4ab1-7b93-bd6d-31a0f3bba429`：40.063秒完成，资料MCP和网页调用均为0；本例没有命中首选执行指引，最终350个可见字符。它证明无须检索的任务未被新机制强制联网，但不证明每种否定表达都可正确处理。

另加更强负例：用户明确写出technical_research_batch，但同时禁止联网和实际调用，会话 `01a16206-4ada-7ad0-ab70-a5034b83cee8`。该例真实Hook确实注入执行指引，模型仍服从用户禁止，资料MCP和网页调用均为0；37.593秒完成，249个可见字符。这验证的是指引已经存在时的排除边界，不用“没注入指引”冒充测试了禁止条件。

`scripts/test-capability-adoption.mjs` 已先建立失败用例再实现修复；覆盖空候选、非首选候选、同名异server、说明大小，以及用隔离本地注册表实际运行Hook确认只输出一次指引，问候不注入。无真实联网，不替代模型行为验收。保留用户禁止检索的语义判断，不为了形式测试引入新的纯关键词评分器。

本机安装check返回零漂移，原9份Prompt、22个Skill和固定提醒节奏一致；四个检索进程图与内存代码一致。13项既有路由正负例、MCP实际客户端、共享HTTP与缓存边界、原始网页证据测试及完整15项PR门禁通过。macOS/Linux没有本轮远程部署验证。
