# 项目从需求到交付

新项目使用 `start-new-project`，先明确用户、范围、约束与真实完成证据，再创建独立仓库。不要把产品源码堆进治理模板。

已有项目先检查当前代码和最新要求。高影响歧义用 `clarify-before-build`；普通可逆修改直接检查相关实现与测试，不先加载整套文档。

先实现一个真实端到端闭环，再扩展边界。复现缺陷后先建立失败测试，再修复拥有该行为的组件。跨组件改变同时验证生产者、消费者与失败语义。

完成前核对真实入口、输入、输出和可追溯结果。窄测试只证明其覆盖的范围；模板发布边界运行 `scripts/check.ps1`。未经运行的部署、跨机恢复和模型采用行为必须明确标为未验证。

有任务树时按项目协议更新最小节点，不擅自移动用户焦点。按既定授权交付 GitHub，凭据和机器信任记录不提交。
