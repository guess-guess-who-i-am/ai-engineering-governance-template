# 共享检索评分的局部修复

已消除逐候选重复判断无关短语分支的一部分 CPU 工作；同图正反两轮的百路短输入 P95 降低约15%～19%，保留单份图和双语模型。**没有恢复历史四进程的3～4秒，也不能宣称所有负载均提速。**

## 机制与验证

原适配器只缓存查询事实，仍对每个候选执行整串短语条件，而且在没有地理意图时也计算地理工具分类。本次按查询事实的真假组合缓存编译后的分支；仅在条件语境将事实转换为布尔值，其它列表、字符串及匹配结果保留原值。地理分类延迟到真正需要的分支，工具条件、乘数顺序、候选池及完整输入保持一致。事实、分支组合和查询计划各自最多缓存256项，均只在内存中。

新增回归测试先在旧实现失败：无关查询对300个候选进行了300次地理分类；修复后0次。原库中英文、韩文短语乘数、嵌套条件、非布尔事实及缓存上限测试通过。编译的是已安装库的函数，不复制另一套评分规则；实现依据为[Python AST 官方文档](https://docs.python.org/3/library/ast.html)的节点替换、语句列表与位置修复规则。Stack Overflow 官方 API 的精确查询无结果，扩大查询后结果不相关，不作为方案正确性的证据；正确性由原函数对照和全图返回值验证。
