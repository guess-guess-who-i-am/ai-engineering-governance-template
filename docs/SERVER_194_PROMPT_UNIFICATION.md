# 194 提示词统一与真实调度验收

日期：2026-10-18。目标：将194的全局治理提示词统一到Mac模板源，降低不必要的串行和模型往返；保持常驻worker运行、开机自动启动，不覆盖认证或停止用户原有会话。

## 修改前定位

- 194旧Hook并没有“一次只能调用一两个”的硬限制：其旧批处理规则本来要求通常5–8路。修改前真实Codex的3轮只读任务全部测得峰值重叠8。因此不能把所有长等待归咎于并发开关或CPU不足。
- 全局AGENTS有一份无标记正文和一份完全相同的受管正文，造成重复；方法论源、路由和发布器目标仍引用旧的 `.agents/routed-skills`，与当前统一图读取的 `.agents/skills` 不一致。
- Mac的V4 Hook要求普通只读波次先从2–4路开始，与中文源已有的通常5–8路偏好不一致。旧三轮状态也不随提示词变化失效，压缩恢复时又不补回调度契约：旧会话可能需要等待下一次固定注入，或者在同轮压缩后丢失调度提醒。

## 本次统一的边界

1. 194的中文编辑源、翻译缓存、中英文生成物、方法论发布器和22个仓库自有治理Skill以Mac模板为源。通过现有发布器 `--check` 验证76条规则的唯一归属和逐字保留；没有手工改生成的英文正文。
2. 发布器及验证器统一使用 `.agents/skills`；去掉全局AGENTS中与受管块完全相同的重复正文，保留真正的用户块外内容。旧目录不作为运行路由或兼容回退。
3. 共用模板升级V5调度契约：已知安全独立工作通常一次发出5–8路，不强制1–2个探针或2–4路预热；依赖、审批、危险和共享状态边界仍保留。平台上限20不是填满目标，较低的用户或接口限制仍须遵守。
4. 确定性DAG执行器默认就绪宽度由4改8，部署到194的全局tools目录；失败/超时减半、危险任务串行、依赖失败跳过和硬上限20均有回归。
5. 通过提示词与调度文本摘要检测政策变化：旧会话下一条请求立即注入新规则，然后恢复三轮节奏；compact/resume当场恢复调度契约，不要求再次输入用户提示。
6. 生产常驻服务保持原PID；开机enabled、Linger=yes，仍为8进程CPU池。失败自动重启不再受短时5次启动限流搁置，连续失败恢复用临时测试服务验证，不终止生产worker。热更新实测后，MemoryHigh调整为22GiB，MemoryMax仍为24GiB，详见下述真实失败与修复。

不复制Mac认证、模型provider、虚拟环境或系统服务文件。两台机器原本都是gpt-6.1-sol/high，保持不变。Linux仍用systemd、CPU-only依赖和Linux绝对路径；本轮没有运行Mac全局安装器去改用户当前Mac会话。

## 真实Codex测试设计

每个批次执行现有Node程序，进行约400ms有限计算并输出编号、实际起止时间和可校验SHA-256结果。验证器必须收齐8个不同编号、正确结果、成功退出与真实区间；模型自述不计证据。纯串行和并行合成区间、重复编号、错误结果及失败命令输出有正/负例测试。

所有轮次使用同一工作目录、相同提示和脚本；先执行修改前3轮，再执行统一后3轮，每轮单独运行以免并发模型请求互相干扰。这个顺序不是随机交错实验，样本也仅3轮/组，不能把中位数差异解释成稳定的因果提速。修改前首轮路由3.473秒，之后已有缓存；后续轮次路由约0.43–0.45秒，缓存状态须与总耗时分开看。
