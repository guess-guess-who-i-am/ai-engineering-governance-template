# 专家排序修复：实测状态与剩余缺口

当前已部署的是候选池的确定修复，**专家精准排序尚未达到可宣布修好的标准**。本文接续[前轮根因报告](EXPERT_RANKING_ROOT_CAUSE_20261030.zh.md)，后续实测以本文为准。名称命中、socket 成功与实际专家执行分别报告，不合并成“准确率”。

## 已部署的修复

`prepare_semantic_candidate_guard` 已经取得有效语义候选时，上游因弱类别信号返回 `None`，却仍使全库进入后续评分。现在将实际字面、全局语义和类内语义候选用于有界评分；没有有效向量时不虚构候选。最终专家/Skill/MCP 的 2/4/2 配额不变。

20 个真实需求各运行一冷三暖，同图前后共 160 次测量：返回的八项身份、名单、顺序全部一致；酒店用例的个别 `score` 有小变化，因此不能声称所有输出字段逐字一致。

| 测量 | 修复前 | 修复后 |
|---|---:|---:|
| 最大候选池 | 19,754 | 500 |
| 酒店用例候选池 | 19,754 | 92 |
| 酒店用例暖中位耗时 | 831.104 ms | 20.296 ms |
| 全部需求暖中位耗时 | 119.676 ms | 129.081 ms |

没有总体提速证据。两个独立进程的计时还受机器负载影响，单用例收益不能外推成全局倍率。

全局部署后，20 个不同需求经 8 路客户端全部成功，由 4 个常驻查询进程实际处理；仓库外 `/tmp` 的真实 dispatcher 保持 2/4/2。原图及向量 sidecar 没有因本次代码替换改变，未修改 Hook 信任记录。该真实越权需求仍返回法律专家，直接证明本修复没有解决语义排序。

## 排序实验

所有推理免费、本地、与生产隔离。20 条开发需求已被反复观察，另 12 条为针对已知机制编写的对照，均不是独立总体 benchmark。原专家包、主角色及成员流程没有改写。

| 方法 | 查询中位耗时 | 决定是否部署的反例 |
|---|---:|---|
| Qwen3-Reranker-0.6B，短双语说明、类内召回 50 | 6,839.588 ms | 腾讯 Omics、SOC、算卦、求职者角色仍占据错误任务的席位 |
| mMARCO 小型多语重排 | 600.963 ms | 应用越权推荐 RTC 日志；酒店推荐配送 |
| GTE 多语重排 base | 1,874.752 ms | 模型评价仍推荐 Skill 制作与招聘；考试推荐留学 |
| Qwen3-Embedding-0.6B，同双语说明 | 58.687 ms | 当前需求仍偏向制作 Skill；主题边界错配 |
| Qwen3-Embedding-4B，MLX 4bit，同双语说明 | 238.154 ms | 改善若干需求，但越权仍偏 SOC，指标审计仍偏 Skill 制作 |
| 同一 4B，原文职责段落 20 条 | 410.097 ms | 指标审计仍把 Skill 制作专家排第一；应用越权需求仍有领域错配 |
| 同一 4B，12 条职责边界对照 | 219.399 ms | 自建系统越权修复和腾讯内部规范查询仍共享同组安全专家 |
| Qwen3-Reranker-4B，冻结 16 专家候选、完整原角色 | 25,398.862 ms | 12 条前列首席多与各任务一致，但知识库、候选招聘、浏览器证据等第二席/顺序仍有错配；推理过慢，不部署 |

4B 的 446 个短说明向量离线构建耗时 176.490 秒，矩阵 4,567,040 字节；实测峰值 Metal 分配约 3.12 GB，不等于新增常驻 RSS。职责段落向量离线构建耗时 1,336.106 秒；可复用的 4.57 MB 仍是每专家一个向量，没有拆开专家包。Reranker 另需约 3.15 GB Metal 分配，每条查询约 25.4 秒。两种排序实验都未接入全图真实入口，不能据此声称生产排序或 Agent 任务成功率提升。

冻结对照的逐席结果：应用授权漏洞首位为 `security-engineer`，次位 `tencent-security-expert`；内部腾讯知识库首位改为 `tencent-security-expert`，但次位 `industry-sre-team` 仍不符；生产事故首位 `incident-response-commander`，次位 `engineering-assurance-team`；支付对账首位 `gl-reconciler`，次位 `finance`；模型评价首位 `model-quality-assurance-expert`，次位 `ai-engineer` 与需求不完全对应；招聘方筛简历前二为 `ihr-ai-interviewer`、`txzhaopin`；求职者辅导前二为 `campus-job-search-coach`、`interview-simulator`；考试计划前二 `exam-preparation-planner`、`study-planner`。其余候选仍按分数展示，不声称全部完成适用性审查。该列表只表示本机定向案例里的首位/前二身份，不是人口准确率或执行成功率。

4B 向量的指标追问案例仍将 `skill-smith` 与 `skillhub-charity-expert-team` 排首二；原角色 reranker 在新职责对照上首席方向较准，但这没有修好该真实追问。继续提高 rerank 深度不能找回阶段一未召回的 `model-quality-assurance-expert`，更不能解决 25 秒延迟。

Qwen3-0.6B 直译查询出现复述翻译指令、遗漏授权漏洞主题及反转否定等问题，未把错误译文继续投入生产。GTE 首次与本机新 Transformers 不兼容；随后在隔离的 4.51.3 运行时取得上述有效结果，没有更改生产依赖。

前报告的 BGE-M3“权重未下载、未运行”是较早状态：后来已完成 446 专家的预训练多向量诊断，1024 长度、离线构建 151.697 秒，token 矩阵 899,958,784 字节，中位总查询 67.713 ms；没有得到稳定适用性优势，未部署。此项使用发布的编码器和投影，未重新训练，不是完整训练复现。

## 当前根因判断

1. **召回证据与最终名额混用**会漏掉池外专家；候选池的全库退化已单独修复，不能用这部分掩盖剩余排序问题。
2. **主题接近不等于任务适用**。应用安全代码修复、云安全运营、内部规范知识库都包含“安全、漏洞、修复”，但输入、工作流、产物和宿主条件不同。更大的通用向量模型仍会混淆，单纯换模型不足以证明修复。
3. **文档表示仍有信息损失风险**。短简介缺少具体职责；部分角色前面有自介绍或安全声明，直接截断可能挤掉真正能力。正在用原文职责段落和更强的原角色重排做可区分的实验；此项尚不是已证实的唯一根因。
4. **评价必须检查两席与宿主依赖**。相关角色排进前二，只是相关性证据；另一席错误、原工作流需要的工具缺失、最终产物未通过验收，都不能算任务成功。
5. **两阶段瓶颈分离**。图召回仍会把职责相关专家漏在候选外（例如指标追问），而大模型可较好排序已经召回的 16 项，却消耗约 25 秒；因此继续扩大候选或同步重排所有候选都不能满足快速准确的目标。

原文复核还纠正了一个潜在误判：`tencent-security-expert` 明确包含 Code Security Review 和 Authentication/Authorization，不能仅因名字或内部知识库定位就判成应用安全需求的“不相关专家”。它同时硬性要求 “Search the knowledge base first, then answer.”，本机是否能完成该流程须单独核验。`soe` 的告警、主机漏洞、入侵和云产品日志职责则不能直接替代应用授权代码修复；`webapp-testing` 可提供回归支持，但其原文将权限越权等专业安全测试另作边界说明。

## 外部证据与适用边界

- [ToolRet](https://aclanthology.org/2025.findings-acl.1258/)，DOI `10.18653/v1/2025.findings-acl.1258`，**ACL Findings，非 ACL 主会**。已读原文：工具检索存在任务迁移，普通重排可能负收益；其训练使用检索到的负例。本文不把论文结果当作本机收益。
- [Sentence Transformers 领域适配](https://sbert.net/examples/sentence_transformer/domain_adaptation/README.html)：查询生成、难负例、交叉编码器伪标签及蒸馏。尚未在本项目训练，不能称已复现；同批专家也不能一律当作真负例。
- [Tool2Vec](https://github.com/SqueezeAILab/Tool2Vec)：离线使用驱动表示，与简单替换编码器不同；仓库并非高 star，未把其推荐方法冒称成现成生产能力。
- [FlagEmbedding](https://github.com/FlagOpen/FlagEmbedding) 本轮检索约 12,289 stars。其维护状态和训练实现是候选依据，不能代替本机效果验证。
