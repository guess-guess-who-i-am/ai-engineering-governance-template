# IDE 与当前本机 Codex 配置对齐

当前行为以用户级已安装配置为准：`~/.codex/config.toml`、`~/.codex/AGENTS.md`、`~/.codex/hooks.json`、`~/.codex/prompts/`、`~/.agents/skills/`，以及 `~/.codex/skill-registry/external-library-config.json` 指向的完整外部库。IDE 共用这些资源，不复制一套工作区 Skill，也不以旧仓库快照覆盖当前安装。

IDE 的规范源码位于 `/Library/hyf/并行ide/llm-task-tree-macos/llm-task-tree-kit/server/`。`codex-resource-parity.js` 通过本机 Codex app-server 的 `skills/list` 和 `config/read` 取得启用入口的完整元数据及有效配置，配置发现连接可被并发工作区复用；它不发模型请求。项目指令发现遵循 Git／配置根标记、override 优先级、fallback 文件名和字节预算。入口目录按预算展示，完整 Skill 正文及专家原包仍按需读取。

本仓库补齐了另一处版本差异：部署源的 context-refresh 仍是V4，而当前安装已是V5；同步现有V5实现及已发布方法论的源、翻译缓存和校验收据。规则内容变化时立即重注入，compact／resume恢复V5；普通提示保持第1、4、7…轮固定提醒，每轮继续检索Skill。没有重新翻译或改写现有规则。

## 验收证据

- 两个独立临时工作区中，37个启用入口的名称、路径及完整描述均与独立导出的Codex原生目录一致；初始展示预算8000字符，保留全部37个名称与路径，36条描述按预算缩短。缩短的是初始展示，按需发现时完整描述逐字匹配。
- 实际IDE读取同一配置文件及哈希，Agent上限20，AGENTS及Hook来自同一用户级文件；两工作区四轮实际Hook均为固定提醒“有、无、无、有”，每轮都能检索当前Skill。
- 15497个图Skill、4232个资源模块继续共用；两个工作区的专家、Skill及MCP描述全文与全局文件匹配，专家登记数447。
- 当前常驻检索服务的四次并发请求使用同一入口进程、四个不同计算进程；中英文检索及预过滤均就绪。真实研究MCP和node_repl的握手、工具Schema发现分别返回2个和4个工具；该检查不等于已执行所有工具。
- Agent容量及自适应工具波次的15项测试通过，其中100个会话共享20个执行名额。V5回归先在旧部署源重现规则变更被跳过，再在同步后通过；完整Mac安装、25个治理Skill、任意工作区服务入口及回滚测试通过。仓库15项PR门禁通过。
- IDE核心及共享Worker的20项定向回归通过且无跳过；三个分发副本的5个消费文件逐项哈希一致。两个工作区通过同一个真实共享Broker读取完整专家原文。再次读取5380、5518的实际服务接口，加载版本均与当前源码版本一致。
- 独立验收器 `scripts/verify-ide-global-parity.mjs` 对真实目录通过；故意改变原生目录的一条描述后，它明确拒绝通过，避免仅凭“登记成功”作结论。
