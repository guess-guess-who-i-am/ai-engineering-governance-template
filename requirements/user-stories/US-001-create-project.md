# US-001: 从治理模板创建独立项目

## 用户故事

- Actor: 使用 Codex 启动新项目的开发者
- Need: 根据项目 brief 创建独立、本地可验证的 Git 仓库
- Value: 产品代码与治理模板分离，同时保留一致的需求、测试和 CI 证据链

## 验收条件

### AC-001: 生成第一条端到端需求链

- Type: happy
- Given: 用户提供合法的仓库名、受众、结果、第一条闭环和项目类型
- When: 非交互运行新项目脚本
- Then: 新仓库包含 brief、上下文、首条用户故事和完整质量门禁清单，并通过 PR 级检查

### AC-002: 发布前不允许静默缺少产品测试

- Type: failure
- Given: 新项目尚未为技术栈配置单元、集成、端到端、性能和安全等产品门禁
- When: 执行发布级质量检查
- Then: 检查明确列出所有未配置的必需门禁并失败，而不是给出虚假的绿色结果

## 证据映射

- AC-001: file=scripts/test-new-project.ps1; gate=template-bootstrap
- AC-002: file=scripts/test-new-project.ps1; gate=template-bootstrap

## 测试设计矩阵

- 主成功路径: AC-001: 用合法 brief 从真实脚本生成可检查的独立仓库
- 业务失败与恢复: AC-002: 发布门禁因产品测试未配置而失败，且本地项目仍可继续配置
- 边界与重复操作: AC-002: 覆盖缺少必需门禁和不完整项目状态，重复生成使用隔离目标目录
- 性能与容量: N/A: 当前不承诺项目生成时延或吞吐，生成项目会保留发布前必须处理的产品性能门禁
- 身份与权限: AC-002: GitHub 未授权时不得把本地生成误报为远程发布成功
- 兼容与历史数据: N/A: 新项目写入全新目标目录，不读取或迁移旧版本业务数据
- 持久数据与副作用: AC-001: 检查生成文件、Git 仓库和质量清单；AC-002: GitHub 失败不得丢失本地项目

## 协作触发点

- 需求评审: 生成器字段或项目边界变化前，由模板维护者、目标项目使用者和测试确认 brief、凭据边界及目标目录
- 用例评审: 修改生成结果或门禁清单时，由脚本维护者和测试核对成功、缺项、重复运行及远程失败场景
- 阶段交付: 每次生成器可运行版本交付提交号、临时目标目录、调用参数、生成仓库和开发自测结果
- 缺陷与回归: 生成失败修复后复测原始输入，并回归目录隔离、Git 初始化、门禁清单和远程失败不丢数据

## 非目标

- 不在尚未选择技术栈时伪造具体框架测试。
- 不自动创建远程 GitHub 仓库，除非用户明确授权。
