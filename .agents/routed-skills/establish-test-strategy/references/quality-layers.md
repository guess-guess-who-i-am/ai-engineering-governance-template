# 跨领域质量门禁

## 目录

1. 证据强度
2. 性能
3. 安全与供应链
4. 可访问性
5. CI 分层

## 1. 证据强度

从弱到强通常是：静态存在检查、编译/类型、单元、真实依赖集成、契约两端、E2E、部署 smoke、生产遥测。选择与声明同层或更强的证据；更高层不总是更好，因为可能更慢、更脆弱。

## 2. 性能

先定义指标、数据规模、硬件/浏览器、预热、重复次数、基线和允许变化。PR 使用确定性预算；基准多次运行并比较分布；负载测试报告吞吐、并发、错误率和 P50/P95/P99；生产 Web Vitals 只从 RUM p75 得出。

## 3. 安全与供应链

同时覆盖源代码、依赖锁文件、最终制品和运行时权限。Secret/SAST、OSV/SBOM、Trivy、认证授权失败路径和敏感遥测分别拥有不同风险，互不替代。CI 外部 Action 固定 SHA、最小权限、无持久凭据；不对不可信 PR 使用 `pull_request_target`。

## 4. 可访问性

组合静态规则、组件语义测试、键盘/焦点 E2E、对比度与 reduced motion，再进行屏幕阅读器和真实设备抽查。自动工具只能发现部分 WCAG 问题，不能声称完全合规。

## 5. CI 分层

- PR：快速且确定性，阻止行为、契约和安全回归。
- release：所有必需门禁完成，构建和部署制品有证据。
- nightly：网络漏洞库、长耗时矩阵、重复负载和漂移检查。
- qualitative：机械测试完成后，校准模型评价无法稳定编码的意图与表达。

上传结构化报告并保留失败证据。远程 CI 证明 runner/action/secret wiring，本地成功不能替代它。
